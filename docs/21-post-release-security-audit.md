# 21. Post-release security audit

Дата: **27 августа 2026**  
Объект: локальная версия после добавления роли ORGANIZER и Event purge.

## Результат

Критических и высоких уязвимостей в проверенной версии не обнаружено. Проверка
не выявила открытой административной панели без сессии, обхода ролей по прямому
URL, wildcard credentialed CORS, browser JWT, raw auth-token persistence,
production Swagger/OpenAPI, секретов в исходниках или известных high/critical
уязвимостей зависимостей.

## Проверено

- серверная матрица SUPER_ADMIN / ORGANIZER / SCANNER и отрицательные сценарии;
- exact Origin, session-bound CSRF, HttpOnly/Secure/SameSite cookie и отзыв сессий;
- общий MySQL rate limit для login/reset/invitation и отсутствие идентификаторов
  пользователей в bucket keys;
- одноразовые HMAC-ссылки, хранение только hash для session/reset/invitation;
- скрытые production OpenAPI/Swagger и базовые security headers;
- EventAccess для SCANNER и недоступность не назначенного Event;
- SUPER_ADMIN-only purge после archive и typed slug confirmation;
- отсутствие секретов, приватных ключей и локальных env в изменениях;
- dependency audit для production Node и Python зависимостей;
- интеграционные security/regression tests на реальном MySQL 8.1.0.

## Остаточные риски

1. MySQL 8.1.0 завершил поддержку. Это зафиксированное ограничение сервера;
   компенсирующие меры — закрытая сеть, least-privilege accounts, backups и
   письменное принятие риска организацией.
2. Event purge не стирает существующие backup-копии. Они удаляются по штатному
   retention, а восстановление старой копии требует повторить purge до возврата
   приложения в общий доступ.
3. Локальная ревизия и regression suite не заменяют независимый внешний
   penetration test на staging. Такой тест должен проводиться только по
   письменному разрешению владельца инфраструктуры.

## Дополнение r3 — 30 августа 2026

В локальной ревизии изменённых участков проверены серверные роли и EventAccess,
ограничения категорий, конфигурация полей, неизменность исторических миграций,
защита повторной отправки без контактов, обязательность согласия, экранирование
HTML-писем и недоступность черновиков/архива через публичный Event GET.
Повторные отправки содержат случайный requestId; в базе только SHA-256/HMAC,
без копии анкеты. Пароли, токены и рабочие конфиги в пакет обновления не включаются.

Автоматический npm/Python advisory audit: известных уязвимостей не найдено;
приватный пакет event-registration-backend отсутствует в PyPI и пропущен этим
сканером. Исходники и отрицательные сценарии проверены локально. Strix не установлен,
поэтому независимый exploit-validated пентест не выполнялся; не считать эту ревизию
гарантией отсутствия всех уязвимостей или проверкой серверной инфраструктуры.
Риски MySQL 8.1.0 и необходимость проверки реальной HTTPS/SMTP-конфигурации сохраняются.
