# МосАктив: состояние публичного модуля

Проверено по коду 25 сентября 2026 года. Цель: посетитель без входа открывает
рейтинг, находит студента и видит его опубликованное цифровое досье с
мероприятиями, достижениями и происхождением баллов.

## Что уже связано внутри EventKAIT20

Web, Scanner и MosActive — модули одной платформы EventKAIT20. Общие
`Person`, `Registration`, `AttendanceEvent`, `Participation` и журнал баллов
находятся в этом репозитории; отдельная интеграция с внешней системой не нужна.

| Контур | Реализация | Состояние |
| --- | --- | --- |
| Идентичность | Общий `Person`, `StudentProfile`, история `StudentMembership` | Есть; отдельная база МосАктива не требуется |
| Факт участия | `Registration` и `AttendanceEvent` переходят в подтверждённую `Participation` | Есть; заявка сама по себе баллов не даёт |
| Баллы | Версионированные правила и неизменяемый `ScoreTransaction` с AWARD/REVERSAL/MANUAL_ADJUSTMENT | Есть; `NO_RULE` не создаёт начисления |
| Достижения | `Achievement` со статусом проверки | Есть; публично видны только VERIFIED |
| Публикация | `StudentProfile`, активное согласие по отдельным полям, отзыв и аудит | Есть; профиль по умолчанию PRIVATE |
| Публичный путь | `/mos-active`: сезонный рейтинг, поиск, карточка, список участий и достижений, история баллов | Реализован в Web без аккаунта студента |
| Управление | Карточка человека: запись версии согласия, выбор полей, публикация, скрытие, отзыв | Реализовано для SUPER_ADMIN |
| Завершение Event | Ручное завершение или переход через 24 часа создаёт ведомость без баллов | Реализовано; начисление после проверки SUPER_ADMIN/ORGANIZER |
| Контингент | Отдельный XLSX-импорт создаёт приватные профили с нулём баллов; ФИО и группа дают предложение сопоставления | Реализовано для файла с четырьмя согласованными столбцами; реальные данные ещё не загружены |

Публичные ответы отдают фамилию с инициалами и только разрешённые поля. В
истории баллов показываются знак, сезон, дата и тип операции; название
мероприятия появляется только при отдельном разрешении на публикацию участий.
Причины ручных корректировок, внутренние ID и контакты не выводятся.
Подробные коэффициенты Scoring v2 пока не публикуются: сохранённый расчётный
snapshot содержит служебные и потенциально чувствительные данные. Если
посетителю потребуется точная формула каждого начисления, нужен отдельный
безопасный публичный формат объяснения.

Для ближайшего показа на вымышленных студентах нужны сезон, прошлое мероприятие,
уровень и повышение Event, опубликованная версия правил с ролью и уровнем,
назначение политики сезону, отметки Scanner, завершение Event, проверка всей
ведомости и отдельная публикация профилей. Заготовленная policy v2
`KAIT20_DEFAULT` после миграции остаётся черновиком: без опубликованных и
назначенных полных правил ведомость не утверждается. Поздние отметки Scanner
обновляются в очереди, а уже вручную исправленные строки перепроверяются
администратором. Предел одной ведомости — 5000 активных регистраций.

## Что ещё мешает наполнить реальными студентами

1. **Реальный файл контингента.** Отдельный импорт теперь принимает до 5000
   строк XLSX с колонками «Фамилия, Имя, Отчество, Группа» и не объединяет
   существующих Person автоматически. После получения образца файла нужно
   проверить фактические названия колонок, повторяющиеся ФИО и группы,
   провести пробный импорт на вымышленных данных и определить порядок
   разрешения уже существующих записей.
2. **Согласия.** Для каждого публикуемого человека нужно проверить применимую
   версию подписанного согласия и набор разрешённых полей. Наличие человека в
   списке или Event-регистрации не служит согласием на публичное досье.
3. **Агрегированные рейтинги.** Публичные API групп и отделений пока не
   подавляют малые выборки. Их нельзя считать готовыми к запуску с реальным
   контингентом без отдельного решения о пороге и защите от вывода данных.
4. **Эксплуатация с реальными данными.** Тестовая Amvera-база не имеет
   управляемых резервных копий; тестового SMTP нет. Боевой запуск требует
   размещения и проверенного восстановления по инфраструктурному плану.

## Следующий шаг

Получить образец файла контингента без настоящих персональных данных, но с
реальными названиями и типами колонок. По нему сделать независимый импорт
`Person` и учебной принадлежности с предпросмотром и отчётом о конфликтах;
после этого проверить цепочку «импорт → согласие → публикация → рейтинг» на
вымышленных записях. Реальный список загружать только в подготовленную
организационную среду с резервным копированием.

Нынешняя Amvera-версия не обновляется автоматически из этой рабочей ветки:
публикация и проверка публичного адреса остаются отдельным шагом.
