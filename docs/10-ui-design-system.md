# 10. UI / Design System — КАИТ №20

Статус: **Release 1.0 design system**

Источник: пользовательский файл `Контекст_Брендбук_КАИТ20.docx`, выжимка актуальна на 21 августа 2026 года.

## 1. Характер бренда

КАИТ №20 позиционируется как современная технологическая образовательная среда. Ассоциации: развитие вверх, мастерство, цифровая культура, автоматизация, молодость и экспериментальность.

Основная визуальная ось:
- глубокий синий → фиолетовый → пурпурный градиент;
- белая основа;
- много свободного пространства;
- асимметрия;
- один доминирующий акцент;
- модульная сетка;
- диагональная геометрия;
- декор у краёв.

Интерфейс должен ощущаться технологичным и современным, но в студенческой коммуникации — дружелюбным, понятным и человечным.

## 2. Логотип

Использовать только официальный готовый исходник. Не перерисовывать.

Запрещено:
- менять взаимное расположение элементов;
- искажать пропорции;
- наклонять;
- менять слоган/его шрифт;
- добавлять тени, обводки, glow;
- случайно перекрашивать.

На тёмном фоне — официальная белая версия.

## 3. Основные цвета

Подтверждённые значения из переданного контекста:

- сине-сиреневый `#83639D`;
- красный `#CB3334`;
- ультрамариново-синий `#2B2C7C`;
- ярко-оранжевый `#FFA421`;
- сигнальный зелёный `#0F8558`.

В общеинституциональном UI ведущими являются синий, фиолетовый, пурпурный, их градиент и белый.

При расхождениях кодов приоритет:
1. официальный готовый исходник;
2. digital-таблица цветов;
3. RGB;
4. визуальный образец PDF.

## 4. Typography

Фирменный шрифт — Montserrat:
- Bold — заголовки;
- SemiBold — подзаголовки/акценты;
- Medium — основной UI;
- Regular — длинный справочный текст при необходимости.

Minion Pro не включается в web design system.

## 5. UI composition

- преимущественно левое выравнивание;
- короткие заголовки;
- ясная иерархия;
- карточки/таблицы/списки при строгой сетке;
- декоративные элементы не должны мешать data-heavy экранам;
- QR рассматривается как полноценный функциональный элемент композиции.

## 6. Декор

Допустимы дозированно:
- угловатые градиентные плоскости;
- ломаные линии;
- точки-узлы;
- шестиугольники;
- пиксельные сетки;
- диагональные полупрозрачные квадраты;
- геометрия фирменного знака.

Киберпанк из moodboard не является обязательным стилем интерфейса.

## 7. Scanner-specific UX

На экране выбора мероприятия показывается уведомление о новой версии и кнопка
«Обновить Scanner». Она недоступна во время операций; на экране сканирования
обновление не предлагается. Уведомление объясняет перезагрузку и сохранение
очереди отметок. Готовность самого приложения к офлайн-работе и подготовка
данных мероприятия — разные состояния, это явно объясняется оператору.

Установочные иконки Scanner содержат готовый официальный логотип на белом
квадратном поле без перерисовки и изменения пропорций. Manifest ограничен
областью `/scanner/`; для iOS используется отдельная иконка Apple Touch.

Scanner должен жертвовать декоративностью ради скорости:
- крупный QR viewport;
- крупные кнопки;
- высокий контраст;
- мгновенно различимые состояния SUCCESS / ALREADY / INVALID / OFFLINE;
- один доминирующий action;
- минимум текста во время потока.

Сигнальный зелёный может использоваться для SUCCESS; красный — для ошибки. Основной фирменный цвет при этом остаётся сине-фиолетовым.

## 8. Организационные brand assets

При их предоставлении организацией:
- получить официальный logo asset;
- сверить точный основной gradient по digital assets;
- сформировать design tokens;
- подготовить web-safe подключение Montserrat без передачи/публикации исходных font-файлов в документации.

## 9. Рабочие экраны администраторов

- Данные контингента редактируются отдельным блоком карточки человека, с видимыми подписями и обязательной причиной. Объясняется публичность площадки и отсутствие автоматического изменения баллов/видимости при выпуске.
- Несохранённый ввод в этом блоке защищён при уходе; во время запроса поля и выход недоступны. При конфликте версии ввод сохраняется, повторное сохранение заблокировано до сверки; загрузка актуальных данных требует подтверждения сброса местных правок.
- Фильтр «Только возможные дубли» выбирает помеченные сервером карточки и сбрасывает страницу списка. Он не является автоматическим подтверждением совпадения людей.

- На главной странице административные переходы группируются по задачам. Основное действие «Новое мероприятие» остаётся рядом с заголовком; служебные разделы не занимают одну длинную строку.
- Форма мероприятия разделяется на последовательные смысловые блоки: основное, время и места, баллы МосАктив, публикация и регистрация, обложка и описание.
- Проверка участия показывает для каждого зарегистрированного отдельный блок: человек и группа, отметка Scanner, итоговое посещение, роль, результат, сопоставление и сохранение решения. Поиск студента открывается рядом с проверяемой записью.
- Поля форм имеют видимые подписи; при сужении экрана раскладка переходит в одну колонку. Панели и длинный текст не должны вызывать горизонтальную прокрутку страницы. Таблицы с плотными данными прокручиваются только внутри своего контейнера.
- Состояния, ошибки и действия остаются текстовыми и различимыми без опоры только на цвет. Ввод с клавиатуры и видимый фокус обязательны.
- На узком экране Scanner сохраняет крупные действия; его три режима располагаются в две строки.
- Публичная страница МосАктив даёт явные переходы к рейтингу и поиску. Имена, баллы и карточки сохраняют согласованный набор публичных полей.
- В сверке есть поиск по ФИО/группе, фильтры и страницы по 25 записей. Черновики сохраняются при переходах между страницами; общий счётчик учитывает скрытые записи. Утверждение относится ко всему мероприятию, что явно написано рядом с фильтром.
- Пока есть несохранённые карточки, обновление отметок и утверждение заблокированы. Уход со страницы требует решения о черновиках. Во время сохранения поля недоступны, чтобы новая правка не потерялась вместе с завершившимся запросом.
- Успешный ответ утверждения сразу показывает результат начисления; последующее чтение не должно превращать выполненную операцию в сообщение об ошибке.
- Утверждённые ведомости доступны отдельным фильтром. Главный администратор может открыть повторную сверку, указав причину; остальные сотрудники видят её без права редактирования.

- В редакторе мероприятия объясняются обязательные настройки начисления перед открытием регистрации; незавершённую настройку можно сохранить черновиком. Ссылка «Правила начисления» открывает отдельную вкладку `/admin?section=scoring`, сохраняя введённые поля исходной формы. Ошибка указывает конкретную недостающую настройку.
- В карточке мероприятия показываются ошибка автоматической подготовки сверки и время повтора. Формы вместимости ограничены 5000; сообщения о пределе одинаково применимы к потокам и добавлению сверх вместимости.
